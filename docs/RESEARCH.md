# Paperclip — Research Document

Paperclip es un plano de coordinación para compañías de agentes: mantiene compañía, roles, tareas, dependencias, revisiones, ejecuciones y actividad. No es el modelo ni el runtime que razona. Un adaptador inicia un proceso o invoca un servicio; en MEDPULSE, process lanza un ejecutor Node que llama a Codex CLI. Los wrappers realizan operaciones administrativas mediante tokens temporales de ejecución; los modelos interpretan los datos y redactan.

La company delimita recursos y permisos. Cada agente tiene responsable, rol y configuración; las tareas conservan documentos, adjuntos y comentarios. blockedByIssueIds encadena el flujo Director → Sales → Strategy → Outreach. Las políticas de ejecución interceptan done y envían la tarea a una etapa de aprobación humana. Solicitar cambios formalmente requiere una transición con comentario en la misma operación: queda una decisión changes_requested y la tarea vuelve al ejecutor. Un comentario aislado no garantiza esa decisión. Los presupuestos existen en Paperclip; el adaptador process usado aquí no atribuye automáticamente el coste monetario completo del CLI. No presentamos un control de gasto validado.

Paperclip 2026.1106.0 corre localmente en Windows, con Node 24.22.1 y PostgreSQL embebido. La interfaz y API están en loopback. Company, historial y archivos se guardan localmente bajo .runtime, excluida de Git. Codex usa la sesión ChatGPT existente; no copiamos credenciales al repositorio. Los prompts y los datos entregados al modelo salen al proveedor; la base local completa no se publica. El dashboard Vercel solo consume JSON permitido: ninguna credencial ni acceso al servidor local.

La instalación inicial fue pesada y superó diez minutos. codex_local falló al crear un symlink de autenticación en Windows; process permitió ejecución real. La actualización de documentos necesita baseRevisionId: omitirlo causó un 409 real que se conservó y corrigió. Los intentos fallidos pueden requerir reconciliar sus efectos antes de repetirlos. El dry-run ejecuta validación local y registra recibo; no acredita validación o entrega de Meta. El consentimiento y los compradores son sintéticos. Market Intelligence y fuentes externas siguen pendientes; no inferimos demanda desde epidemiología.
